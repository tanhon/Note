谁在循环中主动变化（当前指针），谁就是“枚举”；另一个就是“被维护的数据结构或状态”。

## 枚举左和枚举右的区分

| 维度     | 枚举左    | 枚举右    |
| ------ | ------ | ------ |
| 当前点    | i      | j      |
| 查找范围   | 右边     | 左边     |
| 数据结构   | 很难维护   | 非常适合维护 |
| 是否一次遍历 | ❌ 通常不是 | ✅ 常见   |
| 典型优化   | 排序+双指针 | 哈希表    |
|        |        |        |


## 什么时候用枚举右？

``` cpp
// 定义合适的数据结构——一般是哈希表

for (int j = 0; j < n; j++) {   
// 1. 用左边信息计算答案  
  
// 2. 加入当前信息完成更新  

}
```
### 1️⃣ 需要“找之前出现的值”

关键词：

- “是否存在之前的…”
- “找前面满足条件的元素”

👉 用枚举右

---

### 2️⃣ 可以转化为：

nums[i] + nums[j] = target  
→ nums[i] = target - nums[j]

👉 查“历史值”

---

### 3️⃣ 涉及前缀信息

如：

- 前缀和
- 子数组问题
- 出现次数统计

👉 必须枚举右

---

### 4️⃣ 要求 O(n)

👉 一定是：

> 枚举右 + 数据结构维护左


## 什么时候用枚举左？
### 1️⃣ 两边都要动态（如双指针）

例如：

- 有序数组两数之和
- 三数之和

👉 用：

i + 双指针(left/right)

---

### 2️⃣ 区间问题（固定左端）

如：

- 枚举子数组左端点

---

### 3️⃣ 暴力解 / 没有明显结构优化



## 模型理解

把数组想象成时间轴：

[过去] —— j —— [未来]

- 枚举右：利用“过去”
- 枚举左：依赖“未来”

👉 **算法里“未来”是不可控的，“过去”才是可维护的**

## 坑——在历史信息中找元素

### 1️⃣ `map.contains(cards[i]) && map[cards[i]] > 1`
分两步：
1. `map.contains(cards[i])`  
    → 判断 key 是否存在（**不会插入**）
2. `map[cards[i]]`  
    → **访问值**  
    ⚠️ 如果 key 不存在，会**自动插入一个默认值（0）**
### 2️⃣ `map.find(cards[i]) != map.end()`
- 只做一件事：  
    → 判断 key 是否存在
- **不会插入新元素**
### 3️⃣ `map.count(cards[i])`
等价于第二个，用这个更好


计数  $n*(n-1)/2$  ——等差数列之和、无序两两排列组合的所有可能个数
常用在哈希表统计符合条件的数对 或 总可能情况个数


“两两之和”衍生问题的核心——**对于有两个变量的题目，通常可以枚举其中一个变量，把它视作常量，从而转化成只有一个变量的问题。**
