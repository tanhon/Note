
## 标准框架
```cpp
int left = 0;
for (int right = 0; right < n; right++) {
    // 1 更新窗口状态
    while (窗口不合法) {
        // 2 收缩窗口
        left++;
   }
  // 3 更新答案
}
```



## 关键在于——如何定义“窗口是否合法”
### 1. 频率统计
使用数组或 HashMap 统计字符或数字出现次数。

适用情况：
字符是否重复  
字符出现次数限制  
不同字符数量

示例：

|题目|状态|
|---|---|
|最长无重复子串|map[c]|
|至多K个不同字符|map.size()|
|最小覆盖子串|need / window|

示例代码：

**`map[s[right]]++;`**
**`while(map.size() > k){`**  
    **`map[s[left]]--;`**  
    **`left++;`**  
**`}

### 2. 违规计数
统计 **违反条件的次数**。

适用情况：
最多K次违规

示例：

| 题目         | 违规定义         |
| ---------- | ------------ |
| 最多K个0      | nums[i]==0   |
| 最多一个相邻重复字符 | s[i]==s[i-1] |
| 最多K次替换     | mismatch     |

示例：

**`if (nums[right] == 0) count++;`**
**`while(count > k){`**  
    **`if(nums[left] == 0) count--;`**  
    **`left++;`**  
**`}`

### 3. 窗口代价
维护一个 **窗口消耗值**。

适用情况：
窗口成本 ≤ K

示例：

|题目|cost|
|---|---|
|字符替换|替换代价|
|数组绝对差|abs差值|

示例：

**`cost += something;`**  
**`while(cost > k){`**  
    **`cost -= something;`**  
    **`left++;`**  
**`}`**

### 4. 窗口和、数值累计
维护窗口的 **和或乘积**。

示例：

|题目|状态|
|---|---|
|子数组和 ≤ k|sum|
|乘积小于k|product|

示例：

**`sum += nums[right];`**
**`while(sum > k){`**  
    **`sum -= nums[left];`**  
    **`left++;`**  
**`}

### 5. 单调结构
当需要维护：
窗口最大值 / 最小值
使用 **单调队列**。

示例：

|题目|状态|
|---|---|
|滑动窗口最大值|单调递减队列|
|绝对差限制|maxDeque + minDeque|

### 6. 最后一次位置记录
记录某个条件 **最近出现的位置**。

适用情况：
需要快速跳跃窗口

示例：

|题目|状态|
|---|---|
|最长无重复子串|lastIndex[c]|
|本题优化版|lastPair|

示例：

**`if(last[c] >= left){`**  
    **`left = last[c] + 1;`**  
**`}`**  
**`last[c] = i;`**

### 7. 前缀结构
有些题结合：
前缀和  
哈希

例如：
固定长度窗口  
统计满足条件子数组


## 核心思考——如何选择状态

**先想状态变量，再写代码**


 - ### 题目限制是什么？
	例如：
	最多K个不同字符  
	最多K次修改  
	最多1个相邻重复


- ### 能不能变成“计数”？
	例如：
	不同字符数量  
	违规次数  
	窗口cost


- ### 能不能 O(1) 更新？
	例如：
	right++  
	left++
	
	状态必须能 **随指针移动快速更新**。


涉及到最短子数组通常带着其他条件的问题，一般是当窗口内满足其他条件，但不是最小窗口，此时就要先更新答案，再去缩短窗口（while 循环内部要做的事）。

**越短越合法——当左端点右移时，子数组更容易满足条件**
一般要写 `ans += right - left + 1` ，但怎么得到这个的？
首先，这类题的一个单调性的前提：
如果 【left，right】合法，那么【left + 1 ，right】，【left + 2，right】......【right，right】也是合法的。
<font color="#00b050">left 就是最小的合法左端点，当 right 被固定时，因为只有 left, left+1, ..., right 是合法的，所以有(right - left + 1)种左端点可以配得上当前的 right。</font>
while 循环中写的是条件不满足的情况，然后 left++使条件逐渐满足。
####  越长越合法

一般要写 `ans += left`。
我们把左端点移动到一个「恰好」不合法的位置。什么是「恰好」？就是说 [left,right] 这个子串是不符合要求的，但 [left−1,right] 是符合要求的。由于子串越长越符合要求，所以除了 [left−1,right] 符合要求，更长的 [left−2,right],[left−3,right],…,[0,right] 也符合要求。
所以当右端点**固定**在 right 时，左端点在 0,1,2,…,left−1 的所有子串都是符合要求的，这一共有 left 个，加到答案中。
while 循环写的是条件满足的情况，然后 left++是条件逐渐不满足。


#### 恰好型滑动窗口
例如，要计算有多少个元素和**恰好等于** k 的子数组，可以把问题变成：
- 计算有多少个元素和 ≥k 的子数组。
- 计算有多少个元素和 >k，也就是 ≥k+1 的子数组。
答案就是元素和 ≥k 的子数组个数，减去元素和 ≥k+1 的子数组个数。这里把 > 转换成 ≥，从而可以把滑窗逻辑封装成一个函数 solve，然后用 solve(k)−solve(k+1) 计算，无需编写两份滑窗代码。

**总结**：「恰好」可以拆分成两个「至少」，也就是两个「越长越合法」的滑窗问题。

**注**：也可以把问题变成 ≤k 减去 ≤k−1，即两个「至多」。可根据题目选择合适的变形方式。

**注**：也可以把两个滑动窗口合并起来，维护同一个右端点 right 和两个左端点 left 1​ 和 left 2​，我把这种写法叫做**三指针滑动窗口**。
