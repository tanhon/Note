谁在循环中主动变化（当前指针），谁就是“枚举”；另一个就是“被维护的数据结构或状态”。

## 枚举左和枚举右的区分

| 维度     | 枚举左    | 枚举右    |
| ------ | ------ | ------ |
| 当前点    | i      | j      |
| 查找范围   | 右边     | 左边     |
| 数据结构   | 很难维护   | 非常适合维护 |
| 是否一次遍历 | ❌ 通常不是 | ✅ 常见   |
| 典型优化   | 排序+双指针 | 哈希表    |
|        |        |        |


## 什么时候用枚举右？

``` cpp
// 定义合适的数据结构——一般是哈希表

for (int j = 0; j < n; j++) {   
// 1. 用左边信息计算答案  
  
// 2. 加入当前信息完成更新  

}
```
### 1️⃣ 需要“找之前出现的值”

关键词：

- “是否存在之前的…”
- “找前面满足条件的元素”

👉 用枚举右

---

### 2️⃣ 可以转化为：

nums[i] + nums[j] = target  
→ nums[i] = target - nums[j]

👉 查“历史值”

---

### 3️⃣ 涉及前缀信息

如：

- 前缀和
- 子数组问题
- 出现次数统计

👉 必须枚举右

---

### 4️⃣ 要求 O(n)

👉 一定是：

> 枚举右 + 数据结构维护左


## 什么时候用枚举左？
### 1️⃣ 两边都要动态（如双指针）

例如：

- 有序数组两数之和
- 三数之和

👉 用：

i + 双指针(left/right)

---

### 2️⃣ 区间问题（固定左端）

如：

- 枚举子数组左端点

---

### 3️⃣ 暴力解 / 没有明显结构优化



## 模型理解

把数组想象成时间轴：

[过去] —— j —— [未来]

- 枚举右：利用“过去”
- 枚举左：依赖“未来”

👉 **算法里“未来”是不可控的，“过去”才是可维护的**
<font color="#00b050">利用历史信息，加上现在当下的新信息，去满足题目条件。</font>
<font color="#00b050">因为新信息会在遍历中变成历史信息，所以不需要在历史信息中遍历，而是直接查找索引。</font>
<font color="#00b050">这也是比暴力时间复杂度低的根本原因。</font>

## 坑——在历史信息中找元素

### 1️⃣ `map.contains(cards[i]) && map[cards[i]] > 1`
分两步：
1. `map.contains(cards[i])`  
    → 判断 key 是否存在（**不会插入**）
2. `map[cards[i]]`  
    → **访问值**  
    ⚠️ 如果 key 不存在，会**自动插入一个默认值（0）**
### 2️⃣ `map.find(cards[i]) != map.end()`
- 只做一件事：  
    → 判断 key 是否存在
- **不会插入新元素**
### 3️⃣ `map.count(cards[i])`
等价于第二个，用这个更好


计数  $n*(n-1)/2$  ——等差数列之和、无序两两排列组合的所有可能个数
常用在哈希表统计符合条件的数对 或 总可能情况个数
有时如果要统计数目的 key 值范围较小，可以直接使用数组表示，减少空间复杂度。

“两两之和”衍生问题的核心——**对于有两个变量的题目，通常可以枚举其中一个变量，把它视作常量，从而转化成只有一个变量的问题。**

一些题目要求 `i < j`，为什么先“查询”后“更新”？
先查询 cnt 的历史信息，再更新 cnt，因为题目要求  `i < j`
如果先更新，再查询，就把 `i == j`的情况也考虑进去了

### 枚举中间
对于有三个或者四个变量的问题，枚举中间的变量往往更好算。
为什么？比如问题有三个下标，需要满足 0 ≤ i < j < k < n，对比一下：
- 枚举 i，后续计算中还需保证 j < k。
- 枚举 j，那么 i 和 k 自动被 j 隔开，互相独立，后续计算中无需关心 i 和 k 的位置关系。
所以枚举中间的变量更简单。
 [过去 i] —— j —— [未来 k]

当你能把“左边两个变量”压缩成一个前缀最优量时，枚举 k 是相当简洁的写法。
具体是先假设题目中没有 k 的条件约束，也就是只考虑枚举 j，然后在此基础上去加上枚举 k。这里需要对 for 循环中的变量 x 代表的含义理清楚，最重要的是 x 代表索引，然后一开始的“查找”（也就是更新答案）中的变量 x 代表 k，而之后的 x 分别代表 j 和 i。
类似下面这个：
```cpp
for(int x : nums){
    if(x % 2 == 0){
        ans += cnt_j[x / 2]; // x 代表 k 
    }
    cnt_j[x] += cnt_i[x * 2]; // x 代表 j
    cnt_i[x]++;	// x 代表 i
}
```


### 枚举对角线
给你一个大小为 `m x n` 的矩阵 `mat` ，请以对角线遍历的顺序，用一个数组返回这个矩阵中的所有元素。
![](attachments/Pasted%20image%2020260425214623.jpg)

核心规律：
1. 同一条对角线上的点满足：i + j 相等，令 k = i + j，左上角那条对角线的 k=0，右下角那条对角线的 k = (m−1) + (n−1) = m + n − 2。
2.  第0条对角线（k = 0）：↗（右上）  
	 第1条对角线（k = 1）：↙（左下）  
	 第2条对角线（k = 2）：↗  (右上)
	 ...
	k 为偶数 → 向右上  
	k 为奇数 → 向左下
通过枚举 k 来遍历整个二维数组。

因为 k = i + j，所以知道 i 就能知道 j，可以确定起点：
1. 向右上（↗，i--, j++）  <font color="#00b050">i = min(k, m - 1) ; j = k - i</font>
必须让 i 尽量大（靠下）
原因：
因为 i 会一直减（i--），  
如果起点不够靠下，很快就越界（i < 0），遍历不完整
2. 向左下（↙，i++, j--） <font color="#00b050">j = min(k, n - 1) ; i = k - j</font>
必须让 j 尽量大（靠右）
 原因：
因为 j 会一直减（j--），  
如果起点不够靠右，很快就越界（j < 0），遍历不完整

为什么这里要有 min()？
因为 m 和 n 的大小不一定相等，假设 m = 3，n = 2，k = m + n  = 5，如果右上不加 min，那么 i 的初始取值是 k 也就是 5，但实际上 m = 3，也就是只有 3 行。  

```cpp
class Solution {
public:
    vector<int> findDiagonalOrder(vector<vector<int>>& mat) {
        int m = mat.size(), n = mat[0].size();
        vector<int> ans;

        for (int d = 0; d < m + n - 1; d++) {
            if (d % 2 == 0) {
                // 向右上
                int i = min(d, m - 1);
                int j = d - i;
                while (i >= 0 && j < n) {
                    ans.push_back(mat[i][j]);
                    i--; j++;
                }
            } else {
                // 向左下
                int j = min(d, n - 1);
                int i = d - j;
                while (j >= 0 && i < m) {
                    ans.push_back(mat[i][j]);
                    i++; j--;
                }
            }
        }
        return ans;
    }
};
```


给你一个大小为 `n x n` 的整数方阵 `grid`。返回一个经过如下调整的矩阵：
- **左下角三角形**（包括中间对角线）的对角线按 **非递增顺序** 排序。
- **右上角三角形** 的对角线按 **非递减顺序** 排序。
![](attachments/Pasted%20image%2020260426224115.png)

规律：<font color="#00b0f0">同一条对角线满足 i - j 相等</font>
- 左下区域：i ≥ j → i - j ≥ 0  <font color="#00b050">降序</font>
- 右上区域：i < j → i - j < 0  <font color="#00b050">升序</font>
图中的就是从 -2 到 2 一共 5 条对角线。

```cpp
class Solution {
public:
    vector<vector<int>> sortMatrix(vector<vector<int>>& grid) {
        int n = grid.size();
        unordered_map<int, vector<int>> groups;

        // 分组
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                groups[i - j].push_back(grid[i][j]);
            }
        }

        // 排序
        for (auto& [k, vec] : groups) {
            if (k >= 0) {
                sort(vec.begin(), vec.end(), greater<int>());
            } else {
                sort(vec.begin(), vec.end());
            }
        }

        // 写回
        unordered_map<int, int> idx;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                int k = i - j;
                grid[i][j] = groups[k][idx[k]++];
            }
        }

        return grid;
    }
};
```

关于写回这一步：
`unordered_map<int, int> idx;` 记录每条对角线已经用了多少个元素或者代表下一个元素的下标。
`grid[i][j] = groups[k][idx[k]++];` 
1. 找到当前格子属于哪条对角线（k = i - j）  
2. 从这条对角线的数组中取“下一个值”  
3. 放到 `grid[i][j]`
4. 指针后移

比如：groups[0] = [9, 8, 4]  
访问顺序：  
(0,0) → 取 9  idx=1  
(1,1) → 取 8  idx=2  
(2,2) → 取 4  idx=3
```
[9,   8,   4]  
 ↑  
idx=0  
[9,   8,   4]  
      ↑  
    idx=1  
[9,   8,   4]  
           ↑  
         idx=2
```
