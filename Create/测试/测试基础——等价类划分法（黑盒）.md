# 等价类划分

##### -What ？
根据需求分析，把所用可能的<font color="#ffc000">输入数据</font>分成多个互不相干的子集，这些子集合并后就是整个输入域。

##### -等价类可以分成哪几类 ？
有效等价类——满足需求且合理的
无效等价类——不满足需求或不合理的

##### -How？（划分原则有哪些？）
1. 数值范围原则——有取值范围时，可以划分一个有效，两个无效（小于边界值和大于边界值）。
2. 特定数值原则——规定了必须输入的个数或具体数值，可以划分一个有效，一个无效。
3. 集合原则——输入条件规定了一组确定的值，不同的值有不同的后续处理，可以划分多个有效，一个无效。
4. “必须遵循“规则——比如密码必须以数字开头，可以划分一个有效，一个无效。
5. 细分原则——比如月份，并不是每个月都有 31 天，所以需要拆分。

##### -Why？
如果把所有输入数据一个一个测试，毫无疑问费时费力。通过划分成多个组，每个组内抽出一个代表
元素，用代表元素去完成测试，可以大大减少测试用例。

##### -举例：假设一个网站的注册密码有这样的需求，长度8-16位，必须包含字母和数字。
<font color="#00b050">设计用例核心——只能有一个无效等价类，可以有多个有效等价类</font>

| 输入条件 | 有效等价类   | 编号  | 无效等价类   | 编号  |
| ---- | ------- | --- | ------- | --- |
| 长度   | 8-16 位  | 1   | 小于 8 位  | 3   |
|      |         |     | 大于 16 位 | 4   |
| 组成成分 | 包含字母和数字 | 2   | 不含字母    | 5   |
|      |         |     | 不含数字    | 6   |
|      |         |     | 含特殊符号   | 7   |
|      |         |     | 含中文     | 8   |
|      |         |     | 含空格     | 9   |
|      |         |     | （空）     | 10  |


| 测试用例编号 | 输入数据                 | 预期输出     | 覆盖等价类（编号） |
| ------ | -------------------- | -------- | --------- |
| 1      | abcde12345           | 有效       | 1、2       |
| 2      | abcde12345           | 有效       | 1、2       |
| 3      | a1                   | 长度不足     | 2、3       |
| 4      | abcdefghijk123456789 | 超出长度限制   | 2、4       |
| 5      | 0123456789           | 缺少字母     | 1、5       |
| 6      | abcdefghijk          | 缺少数字     | 1、6       |
| 7      | abcde12345!          | 不能涉及敏感字符 | 1、7       |
| 8      | abcde12345六          | 不能包含中文   | 1、8       |
| 9      | abc de12 345         | 不能包含空格   | 1、9       |
| 10     | （空）                  | 输入不能为空   | 10        |
