### 【模块名称】

JVM——垃圾回收机制 GC
### 一、核心问题
这个知识点解决什么问题：
找出没有用的对象，然后回收内存

1. JVM 如何判断哪些对象可以删除？  
2. 删除时用什么方法？  
3. 如何提高回收效率？
### 二、结论
用 3~5 句话讲清本质：

GC 的本质：**回收不可达对象的内存**  
判断方式：**可达性分析（从 GC Roots 出发）**  
回收方法：**三种算法（标记清除 / 复制 / 标记整理）**  
优化核心：**分代收集（新生代 + 老年代）**

### 三、详细过程（流程化）

#### 1️⃣ 判断对象是否存活

- 从 GC Roots 出发
- 看是否能找到该对象
- 找不到 → 垃圾

---

#### 2️⃣ 标记阶段

- 标记所有“存活对象”

---

#### 3️⃣ 回收阶段

- 清理未标记对象

---

#### 4️⃣ 内存整理（可选）

- 移动对象，减少碎片
### 四、关键机制 / 原理

#### 1️⃣ 可达性分析（核心）

👉 本质：图遍历

GC Roots → A → B → C

如果：

GC Roots → A → B     C（断开）

👉 C 会被回收

---

#### 2️⃣ GC Roots 包含

- 栈中的引用
- 静态变量
- 常量
- 本地方法引用（JNI）关键词：native

---

#### 3️⃣ 分代思想（重点）

👉 原因：对象生命周期不同

|区域|特点|
|---|---|
|新生代|对象多，死得快|
|老年代|对象少，活得久|

---

#### 4️⃣ 对象晋升过程

new → Eden → Survivor → Old

### 六、对比 / 易混点
#### GC 算法对比

| 算法   | 优点  | 缺点    |
| ---- | --- | ----- |
| 标记清除 | 简单  | 内存碎片  |
| 复制   | 无碎片 | 浪费空间  |
| 标记整理 | 无碎片 | 移动成本高 |

---

#### Minor GC vs Full GC

| 类型       | 区域  | 特点     |
| -------- | --- | ------ |
| Minor GC | 新生代 | 快      |
| Full GC  | 整个堆 | 慢（会卡顿） |




### 七、代码验证（最小案例）

#### 示例 1：对象变垃圾

```java
public class Test {  
    public static void main(String[] args) {  
        Object obj = new Object();  
        obj = null; // 原对象变为垃圾  
    }  
}

```
👉 原对象不可达 → 可被 GC 回收

---

#### 示例 2：频繁触发 GC

```java
public class GCDemo {  
    public static void main(String[] args) {  
        for (int i = 0; i < 10000; i++) {  
            new Object();  
        }  
    }  
}
```

👉 新生代频繁满 → 多次 Minor GC

---

#### 示例 3：大对象分配

```java
byte[] data = new byte[1024 * 1024]; // 1 MB
```

👉 可能直接进入老年代（取决于 JVM 参数）


### 八 、重点理解

###  GC 本质是一个“图遍历 + 内存管理”问题：

- 用“引用关系”构建图
- 从根节点出发找存活对象
- 删除孤立节点

###  分代的本质是“用空间换时间”：

- 新生代用复制算法（快）
- 老年代用标记整理算法（省空间）

###  JVM 的核心优化点：

大部分对象很快就死 → 专门优化这部分
