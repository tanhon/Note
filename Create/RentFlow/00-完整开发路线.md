## 阶段 10：解决高并发预约

先制造问题，再解决问题。

测试场景：

```
只有一台相机
100个用户同时预约相同时间
最终只能有一个用户成功
```

处理顺序：

1. MySQL 事务内重新检查。
2. 使用条件更新或乐观锁。
3. 增加合理索引。
4. 增加请求幂等键。
5. 使用 Redis Lua 处理限量抢租活动。
6. 必要时使用 Redisson 分布式锁。
7. 执行并发测试。

普通时间段预约和限量活动要分开设计：

- 普通预约：重点是时间冲突和具体设备分配。
- 限量抢租：重点是库存扣减和一人一次。

阶段完成标准：

- 并发测试没有超租。
- 同一个请求重复发送不会产生多条订单。
- 能说明数据库锁、Redis 锁和 Lua 分别解决什么问题。
- 有真实测试报告，而不是只在简历里写“解决高并发”。

学习内容：

- 线程安全
- 乐观锁和悲观锁
- 分布式锁
- Lua 原子操作
- 幂等性
- 唯一索引
- 并发压测
